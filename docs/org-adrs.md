# Org-wide decisions (frostyard/core ADRs)

Conventions this repository follows that are decided at the organization level
are recorded as ADRs in
[frostyard/core](https://github.com/frostyard/core/tree/main/docs/adr)
(core [ADR-0025](https://github.com/frostyard/core/blob/main/docs/adr/0025-consolidate-repository-docs-into-docs.md)
asks every repository to keep these back-links here). Snowcat is a TypeScript
service and also the consumer of core's `organization/` tree, so it is bound in
two ways: as a repository like any other, and as the reader of the contracts
core publishes. Repo-local decisions live in [adr/](adr/); superseded core
ADRs are listed by their successor only.

| [ADR-0035 — Author organization authority as strict JSON](https://github.com/frostyard/core/blob/main/docs/adr/0035-author-organization-authority-as-strict-json.md) | Yes, twice | As a repository: enrollment is authorized only by `organization/repositories/frostyard/snowcat.json` in core, and the surfaces contract v1 names `AGENTS.md`, `policies/agent-governance.json`, `.agents/skills/`, and `docs/README.md` as the canonical surfaces read here. As the consumer: `src/core/validator.ts` and the bundled schemas in `src/core/schemas/v1/` implement the strict-JSON rules (no duplicate keys, unknown fields, symlinks, or unknown versions); see [core snapshot ingestion](design/core-snapshot-ingestion.md). |

| [ADR-0037 — Publish executable organization goals](https://github.com/frostyard/core/blob/main/docs/adr/0037-publish-executable-organization-goals.md) | Yes, as consumer | Goal retention and lifecycle transitions are enforced here against activation history; goals influence discovery and admission but never create or admit work; see [goal ingestion](specs/goal-ingestion.md). |
| [ADR-0038 — make ci stays canonical; the TestI/Integration name filter is chairlift-only](https://github.com/frostyard/core/blob/main/docs/adr/0038-scope-the-test-name-filter-to-chairlift.md) | No (Go-specific); supersedes ADR-0022 | `make ci` and the test-name filter are Go-repository decisions. The analogous rule here is that `npm run check` is the one credential-free gate and `.github/workflows/check.yml` runs exactly it, so a local pass is a CI pass. |
| [ADR-0039 — Widen `maintenance_programs` within repository schema v1](https://github.com/frostyard/core/blob/main/docs/adr/0039-widen-maintenance-programs-within-schema-v1.md) | Yes, as consumer | Snowcat pins schema digests, so it updates its bundled copy in `src/core/schemas/v1/` before core widens an enum, and seeds only the programs it has a catalog entry for (`src/queue/programs.ts`), reporting the rest. |
| [ADR-0040 — Publish the repository settings contract](https://github.com/frostyard/core/blob/main/docs/adr/0040-publish-the-repository-settings-contract.md) | Yes, twice | As a repository: its GitHub settings must match core's organization-wide contract v1. As the consumer: `src/queue/repository-settings.ts` reads the contract, compares live settings read-only, and proposes drift; Snowcat holds no admin credential and applies nothing. |
| [ADR-0041 — Retire copilot-review-apply where Snowcat gates review](https://github.com/frostyard/core/blob/main/docs/adr/0041-retire-copilot-review-apply-where-snowcat-gates-review.md) | Yes | Worker pull requests stay draft through Snowcat's bounded independent review gate; Copilot is requested only when a pull request is ready for a human, and no workflow dispatches an unbounded AI fixer from AI review. |
| [ADR-0042 — Adopt a merge queue on the default branch](https://github.com/frostyard/core/blob/main/docs/adr/0042-adopt-a-merge-queue-on-the-default-branch.md) | Yes, twice | As a repository: the default-branch ruleset carries the merge-queue rule and `.github/workflows/check.yml` runs on `merge_group`, so merging a batch of gate-released pull requests needs no update-and-wait per pull request. As the consumer: the bundled repository-settings schema accepts `merge_queue: true` and the settings sweep reports a missing queue rule as drift. |

When changing behavior covered by one of these, update or supersede the ADR in
frostyard/core first, then change this repository in the same effort. Add a
row here when a new core ADR starts to bind this repository, and replace a row
when core supersedes the ADR it cites.
